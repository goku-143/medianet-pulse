# Pulse: incident-first anomaly alerting for ad campaigns

Prototype for the **Media.net Associate Product Manager case study** (topic: *alerting system for anomalies in ad campaign performance*).
Built by **Shubham Meena**, IIM Lucknow.

**Live demo:** `https://goku-143.github.io/medianet-pulse/`

## The problem
Campaign teams don't need *more* alerts. Static rules ("alert if a metric moves ±30%") fire thousands of times a week, most of them noise, so people mute them, and the costly problems (a broken pixel, bot traffic, a runaway budget) slip through for hours.

## What Pulse does differently
| | Typical alerting | Pulse |
|---|---|---|
| Unit of work | One alert per metric per campaign | **One incident per root cause** (a pixel outage on 7 campaigns = 1 incident) |
| Baseline | Yesterday, or a fixed number | **Same hour, last 7 days, median**, so daily and weekly cycles don't look like anomalies |
| Priority | Size of the % change | **$ at risk per hour × confidence** → P1 / P2 / P3 |
| Output | "CTR changed 42%" | Likely cause, evidence, what was ruled out, one-click **human-approved** fix |
| Edge cases | Noise | Freshness guard (late data), context calendar (planned sales), minimum volume, materiality floor |

## Try it
1. **Live incidents:** three issues are running when the page loads: a pixel outage, bot traffic on a supply cluster, and creative fatigue.
2. **Scenario lab:** inject a budget runaway, publisher outage, broken landing page, reporting delay or sale-day surge, and watch Pulse respond.
   - *Reporting delay*: switch the freshness guard off to see the flood of false alarms it prevents.
   - *Retail sale surge*: tick the context calendar to see expected spikes suppressed.
3. **Thresholds & backtest:** move the sliders. Each change re-runs a backtest on 6 days of history with 10 labelled incidents and plots the recall / precision / alert-volume trade-off.
4. **Notifications:** routing policy, Slack / SMS / digest previews and anti-fatigue rules.
5. **How it works:** pipeline, trigger rules and thresholds, metrics, rollout.

Backtest at the recommended defaults (z = 3.5, 2 h persistence): **10 of 10 incidents caught, about 12 incidents a week, median 1 h to detect**, versus about 14,000 alerts a week from the naive ±30% rule.

## Tech
A static site with no build step and no backend: `index.html`, `styles.css` and `app.js` (vanilla JS) plus Chart.js from a CDN.
All data (124 campaigns, 12 advertisers, 8 supply clusters, 14 days of hourly metrics) is generated by a seeded simulator in the browser, so every visitor sees the same story.

## Host on GitHub Pages
1. Push this folder to a public repo named `medianet-pulse`.
2. Open repo **Settings → Pages**, set **Source: Deploy from a branch** and **Branch: `main` / root**, then click Save.
3. After about a minute the site is live at `https://<username>.github.io/medianet-pulse/`.
